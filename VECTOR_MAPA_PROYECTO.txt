==========================

Este archivo es la guía general del proyecto VECTOR.
Debe mantenerse dentro del repositorio y actualizarse cuando cambien
la arquitectura, el formato .imgmap, el funcionamiento del lector o
los objetivos principales del programa.

IMPORTANTE
----------
Este documento distingue entre:

1. ESTADO ACTUAL DEL REPOSITORIO:
   Lo que realmente existe y funciona en el código actualmente publicado.

2. OBJETIVO / FUNCIONAMIENTO PREVISTO:
   Lo que se decidió que VECTOR debe llegar a hacer.

Si hay una diferencia entre ambos, no se debe asumir que una función
prevista ya está implementada.

======================================================================
1. QUÉ ES VECTOR
======================================================================

VECTOR es un programa para Windows destinado a crear y leer archivos
de mapas de imágenes con extensión:

    .imgmap

Un archivo .imgmap representa un conjunto organizado de imágenes.

La idea principal es que un .imgmap tenga:

- una portada raíz;
- varias ramas;
- una portada propia para cada rama;
- varias imágenes dentro de cada rama;
- un manifest interno que describe la estructura del archivo.

El lector de VECTOR debe mostrar este contenido de forma rápida,
continua y cómoda, especialmente para mapas/documentos formados por
muchas imágenes.

El proyecto comenzó con un lector basado en tkinter + Pillow
(reader.py), pero el desarrollo actual está migrando el lector a una
interfaz HTML/CSS/JavaScript mostrada dentro de una ventana nativa
mediante pywebview (reader_web.py).

3. MAPA DE ARCHIVOS
======================================================================

3.1 mapformat.py
----------------

Es la parte central del formato .imgmap.

No depende de librerías externas; utiliza la biblioteca estándar de
Python.

Define:

    MANIFEST_NAME = "manifest.json"
    FORMAT_VERSION = 1
    EXTENSION = ".imgmap"

Formatos de imagen aceptados:

    .jpg
    .jpeg
    .png
    .webp

Funciones principales:

    _find_cover(...)
        Busca una imagen cuyo nombre base sea "portada".

    _extract_number(...)
        Extrae el ÚLTIMO número presente en el nombre de archivo.

    _list_branch_images(...)
        Obtiene las imágenes de una rama y las ordena por el número
        encontrado en su nombre.

    build_from_folder(...)
        Construye un archivo .imgmap desde una carpeta.

    read_manifest(...)
        Lee manifest.json desde el .imgmap.

    read_entry(...)
        Lee una entrada concreta del archivo .imgmap.

    total_image_count(...)
        Cuenta las imágenes de todas las ramas.

REGLA DE ORDEN DE IMÁGENES
--------------------------

El orden de las imágenes de una rama se obtiene buscando el último
número del nombre.

Ejemplos:

    1.jpg
    pagina_07.png
    49 (12).jpg

El número utilizado para ordenar respectivamente sería:

    1
    7
    12

Si una imagen no contiene ningún número, el creador actualmente
produce un error.

======================================================================
4. ESTRUCTURA DE UN .IMGMAP
======================================================================

El .imgmap actualmente es un archivo ZIP.

En su interior se guarda aproximadamente:

    portada.jpg
    1/portada.jpg
    1/1.jpg
    1/2.jpg
    1/3.jpg
    2/portada.jpg
    2/1.jpg
    2/2.jpg
    ...
    manifest.json

La portada raíz se almacena en la raíz del ZIP.

Cada rama utiliza una carpeta cuyo nombre corresponde a su número.

Por ejemplo:

    1/
    2/
    3/

Cada rama contiene:

    portada.*
    imágenes de la rama

El manifest contiene información como:

    format_version
    title
    cover
    branches

Cada branch contiene:

    id
    name
    cover
    images

5. CREACIÓN ACTUAL DE UN .IMGMAP
======================================================================

packer_gui.py es el creador gráfico actual.

Flujo actual:

1. El usuario ejecuta packer_gui.py.
2. Selecciona una carpeta raíz.
3. La carpeta debe contener una portada.
4. Debe contener carpetas de ramas numeradas.
5. Puede introducir un título.
6. Selecciona dónde guardar el .imgmap.
7. mapformat.build_from_folder() genera el archivo.

Estructura esperada de la carpeta de origen:

    carpeta_raiz/
        portada.jpg
        1/
            portada.jpg
            1.jpg
            2.jpg
            3.jpg
        2/
            portada.jpg
            1.jpg
            2.jpg
        3/
            portada.png
            1.jpg
            2.jpg

Las ramas deben tener nombres numéricos.

Ejemplo válido:

    1
    2
    3
    10

El creador las ordena numéricamente, no alfabéticamente.

7. LECTOR NUEVO: reader_web.py
======================================================================

reader_web.py es la arquitectura actualmente en desarrollo.

Utiliza:

    Python
        +
    pywebview
        +
    servidor HTTP local
        +
    HTML/CSS/JavaScript

Python no debe encargarse de dibujar las imágenes.
Su función es actuar principalmente como backend local:

- abrir .imgmap;
- leer manifest.json;
- leer imágenes del ZIP;
- servir archivos al frontend;
- comunicarse con JavaScript mediante pywebview.

JavaScript se encarga del renderizado y de la interfaz.

Actualmente reader_web.py:

- crea un servidor local en 127.0.0.1;
- encuentra un puerto disponible;
- sirve el HTML/JS/CSS;
- sirve /manifest;
- sirve /img/...;
- mantiene abierto el .imgmap actual;
- expone choose_and_open() a JavaScript;
- permite abrir un archivo recibido como argumento de línea de comandos.

Uso previsto/actual:

    py reader_web.py

o:

    py reader_web.py "archivo.imgmap"

DEPENDENCIAS
------------

requirements.txt actualmente contiene:

    pywebview>=4.4
    pythonnet>=3.0 ; sys_platform == 'win32'

Por lo tanto, para ejecutar reader_web.py correctamente hay que
instalar:

    python -m pip install -r requirements.txt

En Windows, pythonnet se utiliza para el backend EdgeChromium de
pywebview.

9. FUNCIONAMIENTO DESEADO DEL LECTOR
======================================================================

NAVEGACIÓN GENERAL
------------------

Al abrir un .imgmap:

    HOME
      |
      v
    ROOT
      |
      v
    BRANCH

Al hacer clic sobre una rama:

    ROOT -> BRANCH

Al presionar ESC dentro de una rama:

    BRANCH -> ROOT

Al presionar ESC estando en ROOT:

    ROOT -> HOME

NAVEGACIÓN ENTRE RAMAS
----------------------

Dentro de una rama:

    Flecha izquierda
        -> rama anterior

    Flecha derecha
        -> rama siguiente

Si no existe una rama anterior/siguiente:

    no hacer nada.

El cambio de rama no debe cerrar el .imgmap.

SCROLL
------

Dentro de una rama:

    rueda del mouse -> scroll vertical
    flecha arriba    -> subir
    flecha abajo     -> bajar

Las imágenes deben aparecer una debajo de otra.

La intención visual es una tira continua, similar a un rollo largo
de papel.

No se deben colocar márgenes entre las imágenes.

======================================================================
10. REGLA FUNDAMENTAL PARA LAS IMÁGENES
======================================================================

Las imágenes NO deben deformarse.

Cada imagen mantiene siempre su relación de aspecto original.

El ancho de la imagen se determina mediante un porcentaje del ancho
de la pantalla/viewport.

La altura se calcula automáticamente a partir de la relación de
aspecto.

Ejemplo conceptual:

    ancho = 40% del viewport

Si una imagen tiene relación:

    2:1

su altura será aproximadamente la mitad de su ancho.

Si otra imagen tiene relación:

    1:2

su altura será aproximadamente el doble de su ancho.

Nunca se debe forzar simultáneamente un ancho y una altura arbitraria.

======================================================================
11. ZOOM
======================================================================

El zoom de VECTOR es GLOBAL.

No pertenece a una rama.

No pertenece a un archivo.

Ejemplo:

    rama 1 -> 40%
    rama 2 -> 40%
    rama 3 -> 40%

Si el usuario cambia:

    40 -> 45%

entonces todas las ramas deben utilizar:

    45%

Valores previstos:

    mínimo = 10%
    máximo = 150%
    paso = 5%
    valor inicial = 40%

Por lo tanto:

    40
    45
    50
    55
    ...

El zoom modifica el ancho de las imágenes, manteniendo su relación de
aspecto.

13. BIBLIOTECA
======================================================================

La biblioteca es opcional.

El usuario debe poder elegir una carpeta de Windows.

VECTOR debe recordar esa carpeta.

Dentro de ella se buscan archivos:

    *.imgmap

La biblioteca debe mostrar cada archivo como tarjeta.

Cada tarjeta debe tener:

    portada del .imgmap
    nombre del archivo debajo

No debe mostrarse solamente el nombre.

Al hacer clic en una tarjeta:

    abrir ese .imgmap.

La biblioteca no debe modificar los archivos.

La carpeta elegida puede contener varios .imgmap.

======================================================================
14. CONTINUAR
======================================================================

VECTOR debe recordar cuál fue el último .imgmap abierto correctamente.

La configuración debe guardarse fuera del proyecto, en una ubicación
de usuario de Windows.

La ubicación prevista es:

    %LOCALAPPDATA%\VECTOR\

con un archivo:

    settings.json

La configuración prevista incluye:

    last_file
    library

CONTINUAR debe utilizar last_file.

Si el archivo ya no existe:

    no debe producir un error fatal;
    debe indicar que no existe un archivo reciente.

16. BIBLIOTECA BACKEND PREVISTA
======================================================================

Se prevé crear:

    library.py

Responsabilidades:

- encontrar archivos .imgmap en una carpeta;
- leer sus manifests;
- obtener la ruta de la portada;
- preparar información para la interfaz;
- leer bytes de las portadas.

La interfaz web NO debería recibir una ruta Windows directamente
como si fuera una URL de imagen.

La solución prevista es que el backend proporcione una URL local o
un identificador seguro para que el navegador pueda solicitar la
portada.

Una posible arquitectura:

    biblioteca
       |
       +-- archivo.imgmap
       |      |
       |      +-- manifest
       |      +-- portada
       |
       +-- token interno
              |
              +-- /library-cover/<token>

Esto evita intentar convertir directamente rutas Windows en URLs.

======================================================================
17. SEGURIDAD Y MODIFICACIÓN DE ARCHIVOS
======================================================================

VECTOR es principalmente un lector.

El lector NO debe:

- modificar imágenes originales;
- mover archivos;
- borrar archivos;
- renombrar archivos;
- escribir dentro de los .imgmap abiertos;
- modificar la carpeta de biblioteca.

Abrir y leer un .imgmap debe ser una operación de lectura.

El creador sí puede generar un nuevo .imgmap, pero eso es una
operación separada del lector.

======================================================================
18. VELOCIDAD Y RENDIMIENTO
======================================================================

Una prioridad del proyecto es que el lector sea rápido y visualmente
suave.

El lector web se está utilizando porque el navegador embebido puede
manejar mejor:

- imágenes;
- scroll;
- renderizado;
- lazy loading;
- decodificación asíncrona;
- interfaz HTML/CSS;
- zoom mediante CSS.

Actualmente app.js utiliza:

    loading = "lazy"
    decoding = "async"

para las imágenes.

Esto debe conservarse o mejorarse cuando corresponda.

No se debe volver automáticamente a cargar y redimensionar todas las
imágenes mediante Pillow en el hilo principal si existe una solución
más eficiente en el navegador.

======================================================================
19. ZIP DEL .IMGMAP
======================================================================

Actualmente el .imgmap se genera utilizando:

    zipfile.ZipFile(..., "w", zipfile.ZIP_DEFLATED)

Por lo tanto, actualmente las imágenes están comprimidas dentro del
ZIP.

OBJETIVO FUTURO:

Utilizar ZIP STORE en lugar de DEFLATED para las imágenes.

Motivo:

Las imágenes JPG/PNG/WebP ya están comprimidas.

Volver a comprimirlas dentro del ZIP consume CPU y puede empeorar la
velocidad de acceso.

La idea futura es almacenar las entradas sin compresión:

    ZIP_STORED

Esto debe hacerse posteriormente, cuando la interfaz y el lector estén
funcionando correctamente.

NO hacer este cambio antes de estabilizar la arquitectura salvo que
sea necesario para una prueba específica.

27. REGLAS PARA MODIFICAR EL PROYECTO
======================================================================

Cuando se modifique VECTOR:

1. Revisar primero el estado real del repositorio.

2. No asumir que una modificación propuesta anteriormente ya fue
   aplicada.

3. No duplicar funcionalidades.

4. No mantener dos arquitecturas diferentes sin una razón clara.

5. Si se reemplaza un archivo, entregar el archivo completo cuando
   sea razonable.

6. No entregar dos archivos distintos dentro del mismo bloque de
   código.

7. Mantener separadas las responsabilidades:
       formato
       backend
       configuración
       biblioteca
       interfaz
       lector

8. No romper el formato .imgmap existente sin una razón explícita.

9. Mantener compatibilidad con archivos .imgmap ya creados cuando sea
   posible.

10. El lector debe ser de solo lectura respecto de los archivos
    abiertos.

11. Las imágenes nunca deben deformarse.

12. El zoom debe ser global.

13. La portada raíz no se muestra en ROOT.

14. La portada de cada rama sí se muestra en su tarjeta.

15. La biblioteca muestra portada + nombre.

16. Esc vuelve atrás.

17. Izquierda/derecha cambian de rama únicamente si existe una rama
    anterior/siguiente.

18. No introducir dependencias externas innecesarias.

19. Antes de cambiar una dependencia, revisar requirements.txt.

20. Para problemas del proyecto, usar el código real del repositorio
    como fuente de verdad.

======================================================================
29. PROBLEMA ACTUAL DE EJECUCIÓN CONOCIDO
======================================================================

Al ejecutar:

    python reader_web.py

se produjo:

    ModuleNotFoundError: No module named 'webview'

Esto no significa que el código de reader_web.py tenga necesariamente
un error de importación.

Significa que el entorno Python utilizado para ejecutar el programa
no tenía instalado pywebview.

La solución prevista es:

    python -m pip install -r requirements.txt

y después:

    python reader_web.py
